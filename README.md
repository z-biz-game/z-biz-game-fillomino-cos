# 埋方块 · Fillomino（零猜测区域格数推理）

一个浏览器原生的 Fillomino：格子里写的不是线索，是**这块的面积**。整本规则只有一句话——

> 每一块相连的同数区域，格数刚好等于它写着的那个数。

没有构建步骤、没有打包器、没有运行期依赖，也没有一个美术或音频文件（板面是 canvas 画的，
音效是 `js/audio/synth.js` 现场合成的）。牌面不落在文件里：`seed + 档位 → 题面` 由
`js/engine/generate.js` 现算，同一个 seed 永远画出同一张盘。

难度不是形容词。每一局屏上那个「难度实测」是 `js/engine/fillomino.js` 的 `solve()` 在**题面**上
跑出来的实测分（`Σ 每条规则用了几次 × 它的权重`），五档的 `band` 是量完之后回填的选择目标。
出货的底气来自两条互相独立的代码，见下面两节。

## 快速开始

```bash
npm start            # http://127.0.0.1:5255/  零依赖静态服务器
npm run check        # 每个源文件 node --check，解析不过就红
npm test             # 引擎层 509 条断言（唯一解、逐格复核、可达性全枚举、档位）
npm run balance      # 难度阶梯实测：每档 40 局，六道关（`SAMPLES=12 npm run balance` 可缩样）
npm run verify       # 门禁：上面两套 + 一个真 headless Chrome 跑 13 个场景遍、655 条断言
```

`tools/verify.sh` 支持三种收窄方式，改哪一段就跑那一段：

```bash
SCENARIOS="hint conflict" bash tools/verify.sh                    # 只跑两个场景
BASE_URL=https://z-biz-game.github.io/z-biz-game-fillomino-cos/ \
  bash tools/verify.sh                                            # 对已部署产物跑同一套断言
SHOTS=local bash tools/verify.sh                                  # 顺手把三张截图落到 tools/shots/
```

端口是这个仓自己的：HTTP **5255** / CDP **9364**。`verify.sh` 在起跑前会先 `curl` 一次并检查
返回的 HTML 里确实有 `fillomino`，所以端口上躺着别人的应用时它是退出码 2，而不是拿别人的页面跑绿。

## 玩法

一格一笔：选中一个数字，点或者拖，把它写进格子。没有「翻转」这回事——盖在自己写过的数上是合法的，
印着的数改不了（引擎的 `setCell` 直接拒，`js/engine/fillomino.js:520`）。

- 调色板 = `擦除` + `1…最大块`，一个不多一个不少（`Game.palette()`，`js/ui/game.js:112`）。
- 键盘：`1…8` 选数字（超过本档最大块的键不起作用）、`0` / `Backspace` / `Delete` 选擦除、
  `H` 提示、`Z` 撤销。
- **拖动** 一次连续写同一个数，整笔算一步、一次撤销全撤；拖过印着的数那几格被跳过。
- **换一局** 抽一个新 seed；**回选档** 随时换档，当前这局会存成续局。
- 纪录按档各存一份，排序先看**没求提示的次数**，再看步数，最后看时间
  （`Store.recordBest`，`js/store.js:95`）——建立在六次提示上的快局不是「我自己推出来的」。
- 进度与纪录只写在本机 `localStorage`（键 `fillomino.save.v1`），没有服务端。

## 一条规则，四条推论

提示只会说这四条（`Rules`，`js/engine/fillomino.js:160`）。权重是「玩家自己想到这一步要多少脑子」：

| 规则 | 权重 | 说的是什么 |
| --- | --- | --- |
| 刚好长满 | 2 | 这块够得着的地方连自己数过来刚好等于它写着的数 → 那些格全得写这个数 |
| 必经之格 | 2.8 | 要凑满 n 格，而绕开某一格最多只能圈到 n−1 格 → 这一格非写不可 |
| 邻区已满 | 1.6 | 挨着的那块已经占满了它写着的数，再塞一格它就多出一格 → 这一格不能是那个数 |
| 只剩一个数 | 2.4 | 把被邻区挤掉的、长不满的都划掉，这一格还能写的数只剩一个 |

四条都只算**这一块自己的账**：它们写下的每一格，在这盘题面的**每一个解**里都成立。所以「铅笔推不出」
永远只是「这四条还定不下这一格」，不是「这一格没有依据」；而提示敢说的每一句，都是能替你算完的。

## 屏上的每个数字是谁算出来的

七个统计全部来自引擎，`js/ui/game.js` 的 `state()` 是唯一口径（`js/ui/game.js:287`）：

| 屏上 | 出处 | 说的是哪本账 |
| --- | --- | --- |
| 步数 / 提示 | `Game.commit()` 计数 | 一步 = 一个手势（一笔拖动算一步）；提示单独记，撤销**不**退这笔账 |
| 已写 | `written / (n − clues)` | 分母是作者留空的格数，不是全盘格数——印着的数不算你写的 |
| 待写 | `diagnose().remaining` | 与上面的分母同源：`n − 已填（含印数）` |
| 成块 | `regions()` 里 `full` 的块数 / 总块数 | 「格数已经对上自己写着的数」的块，不是「写完的块」 |
| 冲突 | `diagnose().violated.size` | 只数区域账对不上的块根（`块大了` / `凑不满`），空格不叫冲突 |
| 难度实测 | `puzzle.score` | 出题时对**题面**跑一遍 `solve()` 算出来的分，与玩家表现无关 |

盘面上还有两套颜色不能混：**底色**按数字分（一个数一种色，`js/theme.js` 的 `DigitFill`），
**描边**按这块的判定分（蓝=还没长满，绿=格数对上了，红=对不上）。描边画在自己格子内侧半个线宽，
因为一条网格线被两块共用，居中画会让一块的判定盖掉邻块的（`js/render/board.js:109`）。

## 唯一解是怎么证的

两套互不信任的代码。`js/engine/count.js` 不共用 `fillomino.js` 的邻接表、区域助手和状态，
它从那句话重新数一遍——要的就是「第一套写错了，错不会同时出现在第二套里」。

1. **铅笔路径** `solve()`：绝不回溯、绝不看玩家墨水。它跑不完，这盘就不出货。
2. **独立计数器** `countSolutions()`：搜索只活在这里。出货条件是它回 `UNIQUE`，
   **并且**它数出的那一份解与铅笔路径的 `derived` **逐格**相同（`js/engine/generate.js:178`）。
3. `OVERBUDGET` 从来不算通过：预算封顶只可能是盘子太大，算「没数完」而不是「数完了」（`js/engine/count.js:8`）。

一条要如实说的边界：**完备 ≠ 可靠**。反向不成立——铅笔推不完盘并不暗示盘有歧解。实测这道缺口相当大：
在「随机擦到同样颗数、不带闸」的对照里，唯一解的盘有 **10/27 铅笔推不完**（`npm test` 打印这一行）。
所以缺口是在**出题时**被闸门封住的，不是靠规则本身完备：`pruneClues()`（`js/engine/generate.js:113`）
每擦一个数字都跑一遍 `solve()`，推不完就擦不掉。同一套对照跑在带闸的出货器上是 **60/60 推得完**、
**60/60 唯一**（`npm test` 的 `gate：出货 60/60…` 那一行，以及 `npm run balance` 的「两道闸」一节）。

## 难度是量出来的

`node tools/balance.mjs` 每档真出 40 局，这张表就是它打印出来的（种子固定，重跑一模一样）：

| 档 | 盘面 | 最大块 | 留字比例 | 目标区间 | 分数 p25 / 中位 / p75 / 最高 | 推理步数中位 | 印数中位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 初学 trainee | 5×5 | 4 | 0.6 | 22…27 | 23.2 / 24 / 24.4 / 25.6 | 10 | 15 |
| 上手 apprentice | 6×5 | 4 | 0.5 | 35…40 | 36 / 36.8 / 37.6 / 39.6 | 15 | 15 |
| 熟练 regular | 6×6 | 4 | 0.5 | 41…46 | 42.4 / 43.6 / 44.4 / 46 | 18 | 18 |
| 高阶 expert | 7×6 | 4 | 0.42 | 52…60 | 54 / 55.2 / 56.4 / 60 | 23 | 20 |
| 大师 master | 7×7 | 4 | 0.45 | 58…67 | 60.4 / 62.4 / 63.6 / 66.8 | 26 | 24 |

五档中位严格递增（24 → 36.8 → 43.6 → 55.2 → 62.4），每档命中自己的区间 40/40，
出货 40/40，独立计数逐格同意 40/40。`band` 是**排序键**不是闸门：区间够不着时照样出货，
只是出货所有试作里离带最近的那一局——`balance.mjs` 用一个 9999…10000 的假带来验这一条确实成立。

出题耗时**报的是尾巴**（中位会骗人：同一档里最慢的一局能到 p50 的十倍）。同一台机器实测：

| 档 | 出题 p25 / p50 / p75 / 最慢（ms） | 一局平均抽几次 | 计数器节点 p50 / 最高 |
| --- | --- | --- | --- |
| trainee | 1 / 1 / 1 / 6 | 1.85 | 230 / 2621 |
| apprentice | 2 / 3 / 5 / 20 | 2.38 | 883 / 10003 |
| regular | 3 / 4 / 7 / 21 | 2.83 | 965 / 11080 |
| expert | 7 / 16 / 36 / **173** | 3.20 | 4584 / 94539 |
| master | 11 / 18 / 44 / **228** | 3.75 | 5287 / 122697 |

墙钟是**观测**，绝不进选盘键（`generate()` 的排序只看 `offBand`，代码里没有任何 `ms` 参与），
所以换一台慢机器不会换出一盘不同的题。`balance.mjs` 里那条 `p95 < 4000ms` 是防「病态变慢」的
兜底，不是性能承诺——绝对值每次都打印，看的是它，不是那条线。

## 门禁

三样东西各自把关，任何一处走样都退出非零：

```
npm run check                       每个源文件能解析
npm test                            509 条引擎断言
npm run doctest                     文档里印着的每个行号，读回真文件对账
npm run balance                     六道关：阶梯单调 / 出货的盘独立计数同意 / 同盘重解同分 /
                                    种下的解过验收器 / 两道闸不空转 / 带只排序
bash tools/verify.sh                655 条真实浏览器断言 + 上面那套文档对账 + 部署集闸
```

`npm run doctest` 管的是纸上的行号：文档每一处「去看第 N 行」都要落在盘上真实存在、且不是整段空白的
那几行；贴着引用写的那个名字必须作为**完整标识符**出现在被指的那几行里（整词，不是子串——短名字坐在
声明长标识符的那一行上也算"出现"，子串口径会把一次真的漂读成绿）。指向别的仓的那几处只数不判：单仓
checkout 读不到别的仓的行号，拿它判红就是一条随环境漂的闸。这一腿不覆盖句子其余部分说得对不对。

浏览器那 655 条来自 11 个场景、13 遍执行（`layout` 在三个窗口里各跑一遍），跑在真 headless Chrome 里，
点的是真 DOM 与真 canvas：

| 场景 | 断言 | 它在盯什么 |
| --- | --- | --- |
| boot | 64 | 首屏与菜单文案、`window.fillomino` 契约、同种子同盘 / 不同种子不同盘，以及一张 **node 量过的题面字面量**——把跨引擎的确定性钉住 |
| paint | 87 | 点与拖的落子、印数改不动、擦除、一次撤销退一整笔 |
| hint | 35 | 每次提示都真推进一格、说的规则真是依据、枯竭与死路都不扣账 |
| region | 45 | 成块判定、邻接、同数相连就是一块 |
| conflict | 60 | `块大了` 与 `凑不满` 的读数、红底红字、以及「看着没错其实走死」那条死路的措辞与坐标 |
| save | 39 | 存档字节数、RLE 往返、只存原始种子、不带走答案 |
| resume | 36 | 续局取回笔迹、步数与**已花的提示数**，并且重绘出同一块盘 |
| reload | 32 | 换一个文档之后存档还在、还是约定好的那一局 |
| records | 34 | 排序键是「先看不求提示几次」：同提示下省步的才算破纪录，靠提示通关的不破 |
| motion | 22 | 动效开关改文案与按下态、减少动效写进 body 和存档、停了动画提示与通关照样成立 |
| layout | 67 | 每格点得中（含四角）、画布不出视口、无横向溢出、图例六色与画布同源、蓝边不冒充绿边 |

`layout` 那 67 条要在三个窗口里都成立，因为 `js/main.js` 的 `availBox()` 在 900 css 像素两侧走的是
两个分支（窄屏按窗口宽、宽屏扣掉面板 340 像素），而 `css/game.css` 的 `@media (max-width: 900px)`
在同一阈值上搬动面板——两处读的是同一个约定，分开看都像对的：

| 窗口 | 分支/列数 | 7×7 的格边长 |
| --- | --- | --- |
| 900×900（门禁默认） | 窄 / 1 列 | 56（撞上限） |
| 1280×900 | 宽 / 2 列 | 56（撞上限） |
| 1024×620 | 宽 / 2 列 | **48**（被窗口高度压下来） |

同一套断言还要在**三种 URL 形态**下都跑绿，因为生产环境和门禁不是同一个 URL：

```bash

BASE_URL=http://127.0.0.1:<p>/z-biz-game-fillomino-cos/ bash tools/verify.sh   # Pages 的前缀形态
```

页内资源全部用相对路径，靠前缀 URL 解析。本地已推的两个形态：根形态与前缀形态各 **655/655**，
逐场景条数一致。

CI 有两个 job（`.github/workflows/ci.yml`），都跑在 `ubuntu-latest` 上。`syntax + engine guarantees` 是

## 已知边界

- **最大块锁 4**。计数器每格走 1..maxK，所以 7×7 配最大块 6 会烧掉六位数的节点：同一台机器各出 4 局
  对照，maxK 4 是 4/4 出货、0 次撞预算、每次调用 40–117ms；maxK 6 是 24 次试作里 **4 次撞预算**、
  每次调用 429–1272ms。整条阶梯因此住在 maxK 4、5×5→7×7 这五格里（量法与结果在 `/tmp` 的一次性脚本里，
  原始判断记在 `js/engine/generate.js:206` 的注释）。
- **`必经之格` 有一个便宜的截断**：一块还能圈到的地方超过 `n+12` 格时这一轮不做绕路勘察。
  它只会少推一步，不会推错一步（漏掉的格本来也没被这条定死）。
- **`reachable()` 是单向的**：它说「不合法」时一定不合法，说「还行」时可能已经死了。
  盘上那个「这笔已经来不及了」只在它报警时出现，从不反过来承诺。
- **高阶与大师的区间重叠**（52…60 与 58…67）：两档的差别是盘面大小与印数密度，
  大师的中位（62.4）确实高于高阶（55.2），但同一分数的两盘是可能各自出货的。
- **减少动效只测了按钮那一路**：`motion` 场景按的是顶栏的动效按钮；系统级的
  `prefers-reduced-motion` 在开机时被读一次（`js/theme.js:109`）并写进同一个设置，但门禁不模拟
  媒体查询，所以这条路是「实现了、没测到」。
- 存档不是防作弊设计：改 `localStorage` 能伪造纪录，这个仓没有服务端可以核对。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`26`）与这一次跑的断言条数（`44`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`26`、断言仍然 `44`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
